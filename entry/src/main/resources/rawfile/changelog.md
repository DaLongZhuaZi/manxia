# 📢 更新日志

> 感谢您使用漫匣！以下是最新版本的更新内容。

## 🚀 v0.1.4 `(105202300)`

### ✨ 阅读与搜索体验 (Reading & Search Experience)

- **统一详情页阅读入口优化**
  > 详情页在不同屏幕方向下都能稳定显示阅读操作，不再让无效布局占用阅读入口。
  - 修复竖屏统一详情页中「开始阅读」按钮受无效占位布局影响而无法稳定显示的问题。
  - 横屏阅读动作固定到右下角，不挤占章节列表高度，并避免浮层遮挡下方面板触摸。

- **搜索历史管理更方便**
  > 搜索历史支持单条清理和一键清空，删除结果会立即同步到本地存储。
  - 长按单条搜索历史即可删除。
  - 搜索历史标题栏新增「清空」按钮，并通过确认对话框避免误操作。
  - 删除与清空会同步更新运行时状态、`AppStorage` 和 `preferences` 持久化数据。

### 🧭 启动与兼容性恢复 (Startup & Compatibility)

- **首屏初始化与 Legado V2 恢复解耦**
  > 冷启动先完成数据库和基础书源索引，较重的兼容编译与图源同步不再阻塞首屏展示。
  - 小说模块启动关键路径只等待数据库和基础书源索引，V2 兼容记录编译及 IMAGE 虚拟图源同步转入启动完成后的后台任务。
  - 后台恢复按书源逐个执行，并在搜索、详情、目录、正文和发现等入口按需确保目标书源已完成兼容恢复。
  - 为恢复任务增加代次、书源身份和共享 Promise 校验，避免删除、换源或重新导入后由迟到结果覆盖当前状态。
  - 统一内容跟踪服务改为关键启动路径完成后初始化，并去重并发初始化请求。

### 🗂 远程书库与欢迎引导 (Remote Libraries & Welcome Guide)

- **Suwayomi / Komga 底栏入口按需显示**
  > 不使用远程书库时保持主页面简洁，需要时可从引导或设置中分别开启入口。
  - Suwayomi 与 Komga 默认不在主页面底栏显示，已有自定义底栏顺序的用户不受影响。
  - 欢迎引导新增两个独立的底栏入口开关和服务配置入口，开启后会将对应标签稳定插入「管理」之前。
  - 引导完成后增加整页上滑淡出过渡，并防止重复触发导航。

### 📤 传书与电子书稳定性 (Transfer & E-Books)

- **配对后的传书上传更可靠**
  > Web 端完成同一局域网配对后，即使上传请求不重复携带令牌或配对码，也能正常继续传书。
  - 修复已配对客户端访问上传接口仍被要求重新提供鉴权信息的问题。
  - 收口传书导入流程、上传服务和导入进度类型，保持大文件传输链路的状态一致。

- **电子书保存、阅读设置与删除更完整**
  > 导入、恢复和删除电子书时，阅读状态及关联文件不再轻易丢失或残留。
  - 保存电子书时保留已有的图片阅读设置和已完成的解压目录，避免并发或懒处理结果被空值覆盖。
  - 删除电子书时清理受管理的电子书目录、封面文件及统一批注数据。
  - 修复 EPUB WebView 划线批注依赖的页面脚本兼容问题，恢复批注渲染；清理 MOBI 转换目标被残留文件占用的情况。

### 🧱 HAR 模块化与资源治理 (HAR Modularization & Resources)

- **多模块职责完成收口**
  > 核心数据、主题、网络、小说、阅读器和功能 UI 的边界更清晰，后续构建与维护更容易定位影响范围。
  - 完成 `manxia-core`、`manxia-theme`、`manxia-network`、`manxia-novel`、`manxia-source-engine`、`manxia-reader-ui` 与 `manxia-features-ui` 等 HAR 模块的职责拆分和消费方导入收口。
  - 设置、搜索历史、漫画数据加载、电子书数据、代理、引导、日志/帮助及远程传输等能力按职责下沉到对应模块，并保留原有功能入口。
  - 各模块补齐显式依赖，清理模块内深路径自引用、冗余依赖和孤儿文件；`manxia-core` 不再反向依赖上层模块。
  - 完成 release 门禁修复与模块化收尾，降低 OhmUrl 解析和增量构建中的隐式依赖风险。

- **共享 UI 资源与编辑器资源集中管理**
  > 资源只保留一份，跨页面使用统一解析入口，同时兼容已有数据中的旧资源键。
  - 新增 `manxia-ui-resources` 共享资源 HAR，通过 `ResourceCatalog` 统一解析媒体、颜色、字符串和系统资源，并提供缺失资源回退与旧键别名兼容。
  - 将公共图片、颜色、字符串和 Markdown/Monaco 编辑器 rawfile 资源分别归属到共享资源模块和功能 UI 模块，移除 entry 与 core 中的重复资源映射。
  - 电子书封面路径支持旧版 `app.media.logo`、`mangabook`、`ebook` 等键的兼容迁移，已有书库数据无需手动修复。

### 🛡 ArkTS 与网络接口兼容性 (ArkTS & API Compatibility)

- **统一异步 API 与类型安全约束**
  > 在保持原有行为的前提下，减少同步调用、隐式类型和跨模块解析带来的运行时风险。
  - Base64、随机数、JWT、Legado data URL、传书分片、网络文件和偏好设置等链路统一迁移到当前 SDK 的异步 API。
  - 为认证、分页、WebView 页面信息、漫画/章节数据、数据库迁移和繁简转换补充明确接口，清理 ArkTS 不支持的动态索引、对象扩展和 `for..in` 等写法。
  - WebView 与 Legado 请求统一显式合并自定义请求头，补强令牌提取、响应字段解析和错误信息归一化，保留原有请求覆盖行为。
