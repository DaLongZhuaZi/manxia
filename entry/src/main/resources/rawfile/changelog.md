# 📢 更新日志

> 感谢您使用漫匣！以下是最新版本的更新内容。

## 🚀 v0.1.4 `(105102300)`

### 💬 反馈中心 (Feedback Center)

- **全新内置反馈系统**
  > 阅读中遇到问题，可以直接在应用内提交反馈，无需跳转到外部渠道。
  - 新增反馈中心页面，支持按「图源 / 书源 / 软件 / 界面 / 建议 / 其他」分类提交。
  - 反馈支持文本、图片、视频与压缩包附件，使用 4MB 分块上传并带自动重试，弱网也能稳定送达。
  - 反馈内容会携带设备型号、系统版本、应用版本等诊断信息，帮助更快定位问题。
  - 反馈接入人机校验网关与本地缓存，未发送成功的反馈会先落盘，待网络恢复后补传。
  - 支持导出与查看反馈日志，便于复现和排查。

### 📖 Legado V2 书源引擎 (Legado V2 Engine)

- **全新 Legado 书源编译与执行引擎**
  > 更完整地兼容开源阅读的 Legado JSON 书源格式，减少书源导入后失效的情况。
  - 新增 `LegadoCompatibilityCompiler`，编译时保留源文档，逐条规则输出诊断与能力报告，问题书源可精确定位到行。
  - 新增工作流编排执行器，统一调度搜索、详情、目录、正文、发现等书源工作流。
  - 新增真实书源 V2 资格跑分器，仅记录脱敏事实并在必需工作流全部通过后才写入验证记录。
  - 支持脚本运行时、请求管线、执行取消与内容语义解析，复杂规则也能按预期运行。
  - 新增 ArkWeb 合规适配宿主与页面，用于书源兼容性自动校验，不干扰正常导航。
  - 大幅增强内置 `legado_runtime` 运行时，跟踪与诊断信息更完整。

### 🔗 分布式接续 (Distributed Continuation)

- **跨端接续更稳定**
  > 连续流转、冷启动落地时，不再出现「数据库未初始化」或遥控器无法拉起的问题。
  - 新增接续落地引导，阅读器 Ability 冷启动时幂等地初始化全局上下文与数据库，避免落地页解析失败。
  - 优化接续状态推进时序，源端自动拉起遥控器改在迁移完成前发起，解决连续流转后源端停留桌面、遥控器无法唤起的问题。
  - 新增分布式权限管理与漫画传输类型定义，接续与传输链路更清晰。
  - 新增接续恢复页面，落地后可直接回到目标阅读位置。

### 🌐 网络传输治理 (Network Transport)

- **网络失败分类与熔断**
  > 区分 DNS、TLS、超时、HTTP 与通用网络错误，避免同一站点反复失败造成无谓等待。
  - 新增网络传输失败协调器，按主机聚合失败原因并生成指纹，短暂熔断可避免连续触发。
  - 新增图源图片传输追踪，传输异常时能输出更完整的诊断信息。

### 🧩 HTML 实体解析 (JSoup Entities)

- **内置 JSoup HTML 实体解析库**
  > 书源规则里的 HTML 实体（如 `&amp;`、`&#39;`）不再依赖外部环境即可正确解码。
  - 新增 JSoup 实体数据与解码脚本，覆盖常见与完整实体集。
  - 新增文本规范化处理，配合 Rhino 沙箱运行时使用，提升书源正文解析准确度。

### 🧪 测试与版本信息 (Tests & Version)

- **补充兼容性与治理测试**
  - 新增 Legado 兼容性一致性测试、执行取消一致性测试、网络传输失败治理测试等。
  - 补充本地单元测试与日志后台输出一致性测试。
  - 当前版本号为 `105002302`，版本名为 `0.1.4`。

## 🚀 v0.1.3 `(105002301)`

### 🔄 漫画单页重试与恢复 (Single Image Retry)

- **新增统一的单页图片重试状态机**
  > 某一页加载失败时，可以单独恢复该页，不再让整章阅读停在错误状态。
  - 新增 `MangaImageRetryCoordinator`，按章节和页面隔离记录自动重试、手动重试、加载中与最终失败状态。
  - 首次失败会自动执行一次缓存优先重试；自动重试仍失败后才展示最终错误。
  - 第一次手动重试继续优先复用有效缓存，后续重试升级为强制刷新并重新请求原始图片。
  - 页面恢复成功后会清理重试状态，下一次失败重新从自动重试阶段开始。

- **统一阅读器中的失败提示与重试入口**
  > 单页、双页和长条阅读中的坏图现在使用一致的恢复方式。
  - `MangaViewer` 在单页、双页、横向双页、预览页和 Webtoon 页面中统一处理组件渲染错误。
  - 最终失败页面会显示独立错误遮罩和重试按钮，不影响同章其他图片继续显示。
  - 重试时刷新图片渲染 key，确保 ArkUI 重新创建图片组件并重新触发加载。
  - 在线已下载内容强制刷新时可切回原始网络地址，避免持续读取已损坏的本地页。

### 🧭 加载生命周期与页面隔离 (Load Lifecycle)

- **避免迟到任务覆盖当前页面**
  > 快速翻页、切换章节或连续重试时，旧请求不会再轻易写回新状态。
  - 每个页面新增加载代次校验，超时或发起新请求后，旧异步结果会被识别并忽略。
  - 图片加载超时会结束当前代次并进入统一失败处理，避免页面长期停留在加载中。
  - 章节、页面集合或组件生命周期变化时会清理重试状态、计时器和渲染代次。
  - 可见页使用更高加载优先级，邻近页和预加载页按用途分级调度。

- **修正 Webtoon 页面索引解析**
  > 长条模式下页面状态和预加载结果会对应到正确的全局位置。
  - Webtoon 模式优先使用页面引用表中的全局 itemIndex，再回退章节内索引。
  - 普通单页和双页模式继续使用章节页面索引，不改变原有阅读进度语义。

### 🗃 缓存强制刷新 (Cache Refresh)

- **强制刷新绕过已有图片缓存**
  > 缓存文件损坏或失败记录尚未过期时，也可以真正重新下载图片。
  - 图片请求新增 `CACHE_FIRST` 与 `FORCE_REFRESH` 重试模式，并将模式纳入请求去重键。
  - 强制刷新会跳过内存缓存、磁盘缓存和失败冷却，避免立即命中上一次的失败结果。
  - 普通加载与强制刷新使用独立任务键，强制请求不会错误等待旧的普通加载任务。
  - 请求参数会完整传递刷新标识、来源类型覆盖和可见页优先级。

- **补充远程书库单页缓存失效能力**
  > Komga 与 Suwayomi 的指定坏页可以单独删除并重新获取。
  - `KomgaCacheManager` 支持失效单页缓存和单图/封面缓存。
  - `SuwayomiCacheManager` 支持按漫画、章节和页码清理指定页面缓存。
  - 缓存删除失败时会停止强制刷新并记录警告，避免继续把旧文件误认为新结果。

### 📚 Komga 与 Suwayomi 阅读器 (Remote Libraries)

- **增强 Komga 单图加载组件**
  > 下载、解码或渲染任一阶段失败时都能进入统一重试流程。
  - `KomgaImage` 增加可选重试能力、加载代次和渲染代次，Komga 阅读器默认启用。
  - 自动重试失败后显示手动重试按钮，后续强制刷新会先失效对应缓存文件。
  - 图片来源变化或组件消失时清理旧状态，并释放不再使用的 PixelMap。
  - 迟到的本地解码或网络下载结果不会覆盖当前图片来源。

- **增强 Suwayomi 下载与 AVIF 解码恢复**
  > 单页下载、图片解码和最终渲染都具备恢复路径。
  - Suwayomi 页面首次失败会自动重试，最终失败后可由用户手动重新加载。
  - 强制刷新时重新获取图片请求头，并清理旧 PixelMap 和页面完成状态。
  - 图片渲染成功后清除失败状态并记录恢复事件；切换章节后丢弃旧章节的迟到结果。
  - 页面退出或重新加载章节时会重置全部单图重试状态。
