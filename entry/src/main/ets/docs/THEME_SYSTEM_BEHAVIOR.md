# 主题系统行为说明

## 主题模式说明

应用支持三种主题模式：

### 1. 浅色主题 (LIGHT)
- **行为**：无论系统主题如何变化，应用始终显示浅色主题
- **用途**：用户偏好浅色界面，不希望跟随系统变化
- **设置方式**：在设置中选择"浅色主题"

### 2. 深色主题 (DARK)
- **行为**：无论系统主题如何变化，应用始终显示深色主题
- **用途**：用户偏好深色界面，不希望跟随系统变化
- **设置方式**：在设置中选择"深色主题"

### 3. 跟随系统 (AUTO)
- **行为**：应用主题跟随系统主题变化
  - 系统为深色模式 → 应用显示深色主题
  - 系统为浅色模式 → 应用显示浅色主题
- **用途**：用户希望应用与系统保持一致
- **设置方式**：在设置中选择"跟随系统"

## 常见场景说明

### 场景1：系统是深色，应用显示浅色
**原因**：用户设置的是"浅色主题"（LIGHT）固定模式

**这是正确的行为** ✅：用户设置的固定主题应该优先于系统主题

**如何改变**：切换到"跟随系统"模式，应用就会显示深色主题

### 场景2：系统是浅色，应用显示深色
**原因**：用户设置的是"深色主题"（DARK）固定模式

**日志示例**：
```

```

**这是正确的行为** ✅：用户设置的固定主题应该优先于系统主题

**如何改变**：切换到"跟随系统"模式，应用就会显示浅色主题

### 场景3：跟随系统模式
**行为**：应用主题实时跟随系统变化

**日志示例**：
```

```

**系统主题变化时**：


## 主题优先级

```
用户设置（LIGHT/DARK）> 系统主题（AUTO模式下）
```

**决策逻辑**：
1. 如果用户设置 = LIGHT → 显示浅色主题（忽略系统主题）
2. 如果用户设置 = DARK → 显示深色主题（忽略系统主题）
3. 如果用户设置 = AUTO → 显示系统主题（跟随系统变化）

## 主题切换方式

### 方式1：通过设置页面
1. 进入"设置" → "主题设置"
2. 选择"浅色主题"/"深色主题"/"跟随系统"
3. 主题立即生效

### 方式2：通过快捷菜单
1. 点击页面右上角菜单
2. 选择"切换主题"
3. 主题在 LIGHT → DARK → AUTO → LIGHT 循环切换

### 方式3：系统主题变化（AUTO模式）
1. 在AUTO模式下
2. 更改系统主题设置
3. 应用返回前台时自动更新主题

## 常见问题

### Q1: 为什么应用主题和系统主题不一致？
**A**: 这是正常的。如果用户设置的是固定主题（LIGHT或DARK），应用主题不会跟随系统变化。只有在AUTO模式下，应用才会跟随系统主题。

### Q2: 如何让应用跟随系统主题？
**A**: 在设置中将主题模式切换到"跟随系统"（AUTO）。

### Q3: 主题切换后需要重启应用吗？
**A**: 不需要。主题切换后立即生效，所有页面会同步更新。

### Q4: 为什么有时候主题切换没反应？
**A**: 可能的原因：
1. 组件没有正确注册主题监听器
2. 日志显示"已向 0 个监听器通知" → 需要检查组件初始化顺序
3. 检查日志中的"已向新监听器通知当前主题"是否存在

### Q5: 如何诊断主题问题？
**A**: 使用诊断方法：
```typescript
const themeManager = ThemeManager.getInstance();
console.log(themeManager.getDiagnostics());

// 输出示例：
// ThemeManager 诊断信息:
// - 初始化状态: true
// - 当前主题设置: light
// - 实际系统主题: dark
// - 最终显示主题: light
// - 注册的监听器数量: 2
// - 存储状态: 已初始化
```

## 技术实现要点

### 1. 监听器注册时机
- ✅ 监听器注册时立即通知当前主题
- ✅ 确保后注册的监听器也能获得正确的初始主题
- ✅ 避免组件错过初始化时的主题通知

### 2. 系统主题检测
- ✅ 正确处理所有 colorMode 值（-1, 0, 1）
- ✅ 应用启动时检测
- ✅ 应用返回前台时重新检测

### 3. 主题持久化
- ✅ 使用 Preferences 存储用户设置
- ✅ 应用重启后保持用户选择

### 4. 主题变化通知
- ✅ 支持多个监听器
- ✅ 线程安全
- ✅ 错误处理
