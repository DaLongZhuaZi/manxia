# 工作流格式兼容性修复

**日期**: 2025-11-18  
**问题**: 工作流解析失败 - "工作流 search 缺少操作序列"

---

## 问题分析

### 错误日志
```
❌ 错误 [MangaSourceConfigParser] 工作流验证失败: 工作流 search 缺少操作序列
```

### 根本原因

**解析器期望的格式与实际JSON格式不匹配**

#### 解析器原本期望的格式（对象格式）
```json
{
  "workflows": {
    "search": {
      "actions": [
        { "type": "navigate", "url": "..." },
        { "type": "extract", "selector": "..." }
      ]
    }
  }
}
```

#### 实际JSON使用的格式（数组格式）
```json
{
  "workflows": {
    "search": [
      { "type": "navigate", "url": "..." },
      { "type": "extract", "selector": "..." }
    ]
  }
}
```

### 代码问题位置

**MangaSourceConfigParser.ets:769**

```typescript
// ❌ 原代码 - 只支持对象格式
const workflowObj = workflow as Record<string, Object>;
const actions = workflowObj.actions as Action[] || [];
```

这段代码假设每个工作流是一个对象，包含`actions`字段，但实际上我们的JSON中工作流**直接就是数组**。

---

## 修复方案

### 支持两种工作流格式

修改`transformConfig`方法，使其同时支持两种格式：

1. **数组格式**（直接）: `"search": [action1, action2, ...]`
2. **对象格式**（嵌套）: `"search": { "actions": [action1, action2, ...] }`

### 修复后的代码

```typescript
// 转换工作流
const workflows = rawConfig.workflows as Record<string, Object>;
const workflowKeys = Object.keys(workflows);
logger.debug(TAG, `解析工作流，数量: ${workflowKeys.length}, 名称: ${workflowKeys.join(', ')}`);

for (let i = 0; i < workflowKeys.length; i++) {
  const name = workflowKeys[i];
  const workflow = workflows[name];
  
  if (workflow && typeof workflow === 'object') {
    let actions: Action[] = [];
    
    // ✅ 支持两种格式
    if (Array.isArray(workflow)) {
      // 格式1：直接是数组
      actions = workflow as Action[];
      logger.debug(TAG, `工作流 ${name} 使用数组格式，操作数量: ${actions.length}`);
    } else {
      // 格式2：对象格式
      const workflowObj = workflow as Record<string, Object>;
      actions = workflowObj.actions as Action[] || [];
      logger.debug(TAG, `工作流 ${name} 使用对象格式，操作数量: ${actions.length}`);
    }
    
    // 根据工作流名称设置到正确的类型
    switch (name) {
      case 'search':
        this.setWorkflowByType(config.workflows, WorkflowType.SEARCH, actions);
        break;
      // ... 其他工作流
    }
  }
}
```

## 支持的工作流格式

### 格式1：数组格式（推荐）

**优点**: 简洁、直观

```json
{
  "workflows": {
    "search": [
      {
        "type": "navigate",
        "url": "{{baseUrl}}"
      },
      {
        "type": "wait",
        "condition": "time",
        "duration": 2000
      },
      {
        "type": "script",
        "code": "..."
      },
      {
        "type": "extract",
        "selector": "script",
        "multiple": true,
        "fields": {
          "id": "id",
          "title": "title"
        }
      }
    ],
    "getMangaDetail": [ ... ],
    "getChapterList": [ ... ],
    "getPageList": [ ... ],
    "getImageUrl": [ ... ]
  }
}
```

### 格式2：对象格式（兼容）

**优点**: 可扩展，可添加元数据

```json
{
  "workflows": {
    "search": {
      "description": "搜索漫画",
      "timeout": 30000,
      "actions": [
        {
          "type": "navigate",
          "url": "{{baseUrl}}"
        },
        {
          "type": "extract",
          "selector": "..."
        }
      ]
    }
  }
}
```

## 总结

### 问题
工作流解析器只支持对象格式（带`actions`字段），但实际JSON使用的是更简洁的数组格式。

### 解决方案
修改解析器同时支持两种格式，使用`Array.isArray()`判断格式类型。

### 结果
- ✅ 解析器现在更加灵活
- ✅ 支持多种图源JSON格式
- ✅ 向后兼容现有图源
- ✅ 更好的调试日志
