# 漫匣局域网传书开发任务清单

> 基于《漫匣局域网传书功能可行性分析与实施建议（修订版）》拆解  
> 更新时间：2026-05-14  
> 当前目标：先完成可迭代的 MVP 主链路，不提前承诺 WebRTC、公网中继、自动发现

---

## 一、范围基线

第一阶段只做以下目标：

1. APP 内可手动开启“局域网传书”服务。
2. APP 展示局域网访问地址、端口、配对码、当前状态。
3. 浏览器直接访问 APP 本地地址，看到状态页和后续上传入口。
4. APP 端预留文件接收、临时落盘、导入编排接口。
5. 后续上传文件类型复用现有导入链路：
   - 漫画压缩包
   - EPUB / MOBI / AZW3
   - PDF
   - TXT

第一阶段暂不纳入验收：

1. `manxia.top/transfer` 自动扫描局域网设备
2. WebRTC P2P 主链路
3. 公网大文件中继
4. 跨公网、跨 NAT、跨子网传输

## 三、当前阶段落地策略

### 3.1 本轮必须落地

1. 新增局域网传书工程清单文档。
2. 新增传书配置与运行时模型。
3. 新增传书配置管理器。
4. 新增传书会话管理器。
5. 新增本地传书服务：
   - TCP 监听
   - 本地状态页 `GET /`
   - JSON 信息接口 `GET /api/info`
   - 最近上传接口 `GET /api/uploads`
   - 配对验证 `POST /api/pair/verify`
   - 原始文件上传 `POST /api/upload`
   - 自动停服计时器
6. 新增上传收件箱服务，负责沙箱落盘和记录管理。
7. 新增传书页面，并展示最近上传记录与“继续导入”操作。
8. 接入设置页入口和主导航。

### 3.2 本轮明确不做

1. `multipart/form-data` 解析
2. 浏览器侧分块续传
3. 导入结果同步到更完整的历史面板 / 通知中心
4. Worker 信令或中继
5. 扫码拉起页

## 四、工程拆解

### T1 基础模型与设置项

目标：

1. 为配置、会话、运行态、HTTP 信息响应建立明确类型。
2. 在 `SettingsManager` 中补充局域网传书相关设置键。

建议设置项：

1. `LAN_TRANSFER_PORT`
2. `LAN_TRANSFER_AUTO_STOP_MINUTES`
3. `LAN_TRANSFER_MAX_FILE_SIZE_MB`
4. `LAN_TRANSFER_ALLOW_BACKGROUND_TRANSFER`
5. `LAN_TRANSFER_WS_ENABLED`

验收标准：

1. 新增类型文件不依赖 `any` / `unknown`
2. 默认值可直接被页面与服务层消费

### T2 配置管理与会话管理

目标：

1. 将设置系统与传书功能隔离，避免页面直接读写零散 key。
2. 提供短时配对码、会话令牌、过期控制。

验收标准：

1. 页面和服务层都通过 Manager 访问配置
2. 会话可刷新、可过期、可清空

### T3 本地服务骨架

目标：

1. 使用 HarmonyOS 已确认可用的 TCP Server 能力启动本地监听。
2. 先实现“浏览器能打开状态页”和“浏览器能拉到 JSON 状态”。

接口范围：

1. `GET /`
2. `GET /api/info`
3. `GET /health`

验收标准：

1. 服务可启动/停止
2. 页面能拿到运行态快照
3. 浏览器访问本地地址时能收到文本页面
4. `/api/info` 可返回结构化 JSON

### T4 页面与导航接入

目标：

1. 让用户能从设置页进入“局域网传书”页面。
2. 页面展示服务状态、地址、配对码、配置摘要。

验收标准：

1. 设置页出现入口
2. 导航路由生效
3. 页面可以启动/停止服务并刷新状态

### T5 上传协议与落盘

目标：

1. 支持浏览器上传本地文件到 APP 临时目录。
2. 限制大小、校验扩展名、返回结果对象。

当前已实现接口：

1. `POST /api/upload`
2. `POST /api/pair/verify`
3. `GET /api/uploads`

验收标准：

1. 上传文件可写入沙箱临时目录
2. 超限、格式不支持、配对失败时可正确返回错误

### T6 导入编排接入

目标：

1. 将上传结果路由到现有导入链路，而不是重新造一套导入系统。

优先复用：

1. `DownloadSyncPage.ets`
2. 现有漫画压缩包导入流程
3. `PdfImportService.ets`
4. 现有电子书解析/导入逻辑

验收标准：

1. 漫画压缩包、电子书、PDF、TXT 至少各有一条明确编排路径
2. 上传记录可由传书页转交给 `DataManagementPage`

当前已补充：

1. 传书记录会在导入成功、失败、取消后回写状态。
2. 浏览器上传页已显示基础上传进度。
3. 浏览器上传页会自动刷新最近上传状态。
4. 传书页已支持复制主地址、复制配对码、复制完整连接指引，以及系统分享连接指引。
5. 传书页已支持二维码展示。
6. 本地 WebSocket 状态通道已接入浏览器上传页并支持运行态 / 上传列表广播。
7. 传书页已支持删除收件箱记录和清理误传文件。

### T7 浏览器端体验增强

目标：

1. 让浏览器上传页具备更明确的状态反馈和更低的操作门槛。
2. 让 APP 页面可以快速把连接信息转发到另一台设备。

当前已完成：

1. 浏览器上传进度条。
2. 上传失败提示与成功提示。
3. 最近上传列表自动刷新。
4. APP 端主地址复制、配对码复制、连接指引复制、系统分享连接指引。
5. APP 端二维码展示与扫码连接辅助。
6. 浏览器端 WebSocket 状态通道接入与回退轮询。

剩余增强项：

1. 更完整的浏览器侧多文件/续传体验。
2. 更细的状态面板与历史记录面板。

### T8 安全与可靠性

目标：

1. 避免一个配对码在短时间内被多个设备混用。
2. 控制收件箱文件和中间态文件的生命周期。
3. 在服务运行期间更及时地把状态变化同步到浏览器侧。

当前已完成：

1. 传书 token 已绑定到已配对客户端 IP。
2. 已配对会话会拒绝其他设备复用当前配对码。
3. 收件箱索引会清理失效记录、超限记录和孤儿文件。
4. 过期 `.part` 文件会在初始化时清理。
5. WebSocket 通道会广播运行态和上传列表变化。
6. 传书页可删除误传或无需继续导入的收件箱记录。
7. 继续导入本身即作为人工确认接收与导入的最终闸门。

### T9 Cloudflare 控制面补充

目标：

1. 把现有零散说明整理成真实可部署的 Worker 工程。
2. 为 `manxia.top/transfer` 提供帮助页和 APP 拉起入口。

当前已完成：

1. 新增 `cloudflare/manxia-worker/` 可部署工程目录。
2. 新增 `/.well-known/applinking.json`、主页、Deep Link 跳转页、`/transfer` 说明页代码。
3. APP 侧已补 `https://manxia.top/transfer` 的 App Linking 和页面映射。

## 六、开发顺序建议

1. 先完成 T1-T4，形成“能开服务、能看页面、能访问本地状态页”的开发基座。
2. 再做 T5，把浏览器上传打通到沙箱临时目录。
3. 最后做 T6，把上传结果接到现有导入体系。

这样推进的原因是：

1. 能尽快验证 HarmonyOS 本地服务端方案是否稳定。
2. 能把风险前置在网络服务和生命周期管理，而不是先陷入文件解析细节。
3. 后续上传协议和导入编排都能建立在已验证的服务基础上继续扩展。
