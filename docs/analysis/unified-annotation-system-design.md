# 统一标注系统方案草案（跨小说/漫画/电子书）

更新时间：2026-03-16
文档状态：讨论稿（仅需求与方案，不涉及代码实现）

## 1. 目标与边界

目标：建立一个跨内容类型（小说、漫画、电子书）的统一标注系统，覆盖以下四类能力：
1. 书签（全内容通用）
2. 划线（仅小说）
3. 想法（仅小说）
4. 汇总页面（用于统一查看、拼接与分享）

边界：
1. 本阶段只定义产品与数据结构方案，不开始开发实现。
2. 方案不照搬 Legado 原版书签结构，采用面向“多内容类型”的统一模型。

## 2. 命名建议（原“引用页”）

推荐名称：`标注中心`

推荐原因：
1. “标注”可以自然覆盖书签、划线、想法，不局限于“引用”。
2. “中心”强调汇总、管理、拼接、分享的入口属性。
3. 用户理解成本低，首次使用也能快速知道这是“所有标注的总入口”。

备选名称：
1. `摘录中心`（更偏文字摘录，书签语义稍弱）
2. `摘录台`（更产品化，但语义略抽象）
3. `标注与摘录`（语义完整，但标题偏长）

## 3. 功能模块定义

## 3.1 书签（跨小说/漫画/电子书）

能力定义：
1. 用户可在当前阅读位置添加书签。
2. 书签可填写一个“书签标记”（短文本），视觉上类似小标题。
3. 书签在内容内可快速跳转，在“标注中心”中可统一查看与管理。

锚点规则：
1. 小说：章节 + 段落/字符定位（支持文本定位回溯）。
2. 漫画：章节 + 页码。
3. 电子书：章节或 spine + 页码/进度。

## 3.2 划线（仅小说）

能力定义：
1. 放在小说阅读器长按工具栏中。
2. 用户可对任意文字或段落划线。
3. 划线后可立即添加想法，也可只保存划线。

样式规则：
1. 线型支持：直线下划线、波浪线。
2. 颜色支持：用户可选颜色。
3. 每条划线样式独立保存，互不影响。
4. 支持“单条划线快捷工具栏”，用于局部修改线型/颜色。

## 3.3 想法（仅小说）

能力定义：
1. 可在划线后直接添加想法。
2. 也支持无划线的独立想法（绑定到当前文本位置）。
3. 想法可在正文中显示轻量入口，在“标注中心”中完整查看与编辑。

关联规则：
1. 想法可绑定某条划线。
2. 想法也可仅绑定文本位置（无划线）。

## 3.4 标注中心（汇总页）

页面职责：
1. 汇总展示书签、划线、想法。
2. 按内容类型、作品、时间、标注类型筛选。
3. 支持多选拼接为“分享稿”。
4. 支持分享到系统渠道（文本、图片卡片等后续扩展）。

核心交互：
1. 列表项点击后可跳回原文/原页。
2. 多选后可排序（手动或按时间）并拼接。
3. 拼接时支持模板化输出（仅文本、带来源、带时间等）。

## 4. 统一数据模型（草案）

建议采用“单主表 + 扩展字段”的统一结构，避免按内容类型拆散。

`UnifiedAnnotation`（主记录）：
1. `annotationId`
2. `contentType`（novel/manga/ebook）
3. `contentId`（作品唯一标识）
4. `annotationType`（bookmark/highlight/thought）
5. `anchor`（定位信息，JSON）
6. `title`（书签标记或条目标题）
7. `text`（想法正文或摘录文本）
8. `linkedAnnotationId`（想法关联划线时使用）
9. `style`（仅划线使用：线型、颜色等）
10. `createdAt`
11. `updatedAt`

`anchor` 建议字段：
1. 通用：`chapterId`、`pageIndex`、`progress`
2. 小说增强：`startOffset`、`endOffset`、`quoteText`、`contextBefore`、`contextAfter`

`style` 建议字段（划线）：
1. `lineType`（underline/wavy）
2. `color`
3. `thickness`（可选，后续扩展）

## 5. 关键交互流程（草案）

流程 A：跨内容加书签
1. 用户在小说/漫画/电子书阅读页点击“添加书签”。
2. 填写“书签标记”（可为空）。
3. 保存后在当前位置展示书签状态，并同步进入“标注中心”。

流程 B：小说划线与想法
1. 长按选中文本，工具栏选择“划线”。
2. 默认应用上次样式（或系统默认样式）。
3. 划线后弹出轻量操作：修改样式 / 添加想法 / 完成。
4. 想法可立即输入，也可后续从标注中心补写。

流程 C：标注中心拼接分享
1. 进入“标注中心”，筛选目标作品或类型。
2. 多选书签、划线、想法条目。
3. 调整顺序并选择拼接模板。
4. 生成分享稿并调用系统分享。

## 6. 与现有架构的衔接原则

1. 复用现有统一内容类型（manga/ebook/novel），避免再建割裂系统。
2. 书签入口要在三类阅读器都可触达。
3. 划线/想法只在小说阅读器暴露入口。
4. 标注中心作为统一入口，不再分散到各子模块独立管理。

## 7. 讨论待确认项

1. 书签标记长度上限（建议 20~40 字）。
2. 小说“独立想法”是否允许无选中文本直接添加。
3. 拼接分享模板第一版包含哪些格式。
4. 是否需要“导出到本地文件（txt/md）”能力。
5. 是否需要“按作品生成标注时间线”视图。
