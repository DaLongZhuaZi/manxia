# 阅读器预加载机制完整分析

## 一、预加载机制概述

### 1.1 预加载配置来源

**是的，预加载受图源设置控制**，配置存储在数据库 `comic_source` 表中：

```typescript
interface SourcePreloadSettings {
  preloadCurrentChapter: boolean;    // 是否预加载当前章节
  preloadCurrentPages: number;       // 当前章节预加载页数
  preloadNextChapter: boolean;       // 是否预加载下一章节
  preloadNextPages: number;          // 下一章节预加载页数（-1表示全部）
}
```

**默认值**：
- `preloadCurrentChapter`: true (1)
- `preloadCurrentPages`: 3
- `preloadNextChapter`: true (1)
- `preloadNextPages`: -1 (全部)

### 1.2 预加载的三个层次

1. **章节页面信息预加载**（MangaReaderPage）
   - 预加载下一章节的页面URL列表
   - 在当前章节加载完成后立即触发

2. **图片URL预加载**（MangaReaderPage）
   - 只是获取图片URL，不实际下载图片
   - 保存到数据库供后续使用

3. **图片PixelMap预加载**（MangaViewer）
   - 实际下载并解码图片为PixelMap
   - 这是真正的图片预加载

private preloadSinglePageWebtoonStyle(): void {
  const currentIndex = this.viewCurrentPageIndex;
  const prevIndex = currentIndex - 1;
  const nextIndex = currentIndex + 1;
  
  // 只预加载前一页和后一页
  if (prevIndex >= 0) {
    const p = this.chapter.pages[prevIndex];
    if (!this.pagePixelMaps.has(p.id) && !this.getPageLoadState(p)?.isLoading) {
      this.loadImage(p);
    }
  }
  if (nextIndex < this.chapter.pages.length) {
    const p = this.chapter.pages[nextIndex];
    if (!this.pagePixelMaps.has(p.id) && !this.getPageLoadState(p)?.isLoading) {
      this.loadImage(p);
    }
  }
}

**这就是问题的根源！**

## 三、问题分析

### 3.1 为什么刚开始加载很快？

因为：
1. **当前页**会立即加载
2. **前一页和后一页**会被预加载
3. 前3页通常在你翻页前就已经加载完成

### 3.2 为什么后面会变慢？

因为：
1. **实际只预加载前后各1页**，而不是图源设置中的数量
2. 当你翻到第4页时，第5页才开始加载
3. 每次翻页都需要等待下一页加载完成

### 3.3 图源设置是否生效？

**部分生效**：
- ✅ `preloadNextChapter`: 生效，会预加载下一章节的页面URL
- ✅ `preloadNextPages`: 生效，控制下一章节预加载的页数
- ❌ `preloadCurrentPages`: **不生效**，实际只预加载前后各1页

## 六、实际加载机制

### 6.1 图片加载入口

```typescript
private async ensurePixelMapLoaded(page: MangaPage): Promise<void> {
  // 1. 检查是否已加载
  if (this.pagePixelMaps.has(page.id)) return;
  
  // 2. 本地图片：直接解码
  if (page.sourceType === ImageSourceType.LOCAL) {
    const pm = await image.createPixelMap(fsPath);
    this.pagePixelMaps.set(page.id, pm);
  }
  
  // 3. 网络图片：通过ImageCacheManager加载
  if (page.sourceType === ImageSourceType.NETWORK) {
    // 检查并发限制
    if (this.networkLoadInProgress >= this.MAX_NETWORK_CONCURRENCY) {
      this.pendingNetworkLoads.push(page.id);  // 加入队列
      return;
    }
    
    this.networkLoadInProgress++;
    const pm = await cacheManager.loadImage(page.imageUrl, opts);
    this.pagePixelMaps.set(page.id, pm);
    this.networkLoadInProgress--;
    
    // 处理队列中的下一个
    this.processNextPendingLoad();
  }
}
```

### 6.2 ImageCacheManager的作用

`ImageCacheManager` 负责：
1. 检查磁盘缓存
2. 如果缓存不存在，发起网络请求
3. 下载并缓存图片
4. 返回PixelMap

## 七、结论

### 7.1 预加载机制的真实状态

| 功能 | 实现状态 | 实际效果 |
|------|---------|---------|
| 章节页面URL预加载 | ✅ 已实现 | 下一章节的URL会提前获取 |
| 图源设置控制 | ⚠️ 部分实现 | 只对下一章节生效 |
| 当前章节图片预加载 | ❌ 未正确实现 | 只预加载前后各1页 |
| preloadCurrentPages设置 | ❌ 无效 | 被硬编码为1覆盖 |

### 7.2 为什么会出现加载等待

1. **预加载范围太小**：只预加载前后各1页
2. **并发限制**：同时最多加载3张图片
3. **网络延迟**：每张图片需要下载时间
4. **没有提前预加载**：翻到第N页时，第N+2页才开始加载

#### 修复2：重构预加载逻辑

修改 `preloadSinglePageNeighbors()` 方法：

```typescript
private preloadSinglePageNeighbors(): void {
  // 使用图源设置的预加载页数，默认为3
  const preloadCount = this.preloadCurrentPages !== undefined ? this.preloadCurrentPages : 3;
  
  // 如果设置为0，不预加载
  if (preloadCount <= 0) {
    return;
  }
  
  const currentIndex = this.viewCurrentPageIndex;
  
  // 预加载前后N页
  for (let i = -preloadCount; i <= preloadCount; i++) {
    if (i === 0) continue; // 跳过当前页
    
    const targetIndex = currentIndex + i;
    if (targetIndex >= 0 && targetIndex < totalPages) {
      const page = this.chapter.pages[targetIndex];
      if (!this.pagePixelMaps.has(page.id) && !this.getPageLoadState(page)?.isLoading) {
        this.loadImage(page);
      }
    }
  }
}
```

#### 修复3：优化动态预加载范围

修改 `getDynamicPreloadRange()` 方法：

```typescript
private getDynamicPreloadRange(): number {
  // 优先使用图源设置的预加载页数
  const configuredPreload = this.preloadCurrentPages !== undefined ? this.preloadCurrentPages : 3;
  
  // 基础范围使用配置值
  let base: number = configuredPreload;
  
  // 根据滚动状态动态调整
  if (this.isScrolling) {
    base = Math.max(2, Math.floor(base * 0.6)); // 滚动时减少
  } else {
    base = base + 2; // 静止时增加
  }
  
  return base;
}
```
