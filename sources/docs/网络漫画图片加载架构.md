# 网络漫画图片加载架构设计文档

## 一、架构概述

本架构基于统一缓存机制，为网络漫画图片建立了完善的加载和显示系统，从根源上解决了图片被锁定显示、UI混合等问题。

### 核心设计原则

1. **统一使用PixelMap显示**：网络图片必须转换为PixelMap后才能显示
2. **三级缓存同步**：OnlineImageLoader → pagePixelMaps → Image组件
3. **严格的状态管理**：确保加载状态与显示状态一致
4. **本地漫画不受影响**：保持现有的本地图片加载逻辑

## 二、问题根源分析

### 问题1：Image组件的缓存机制与状态不同步

**根本原因**：
- HarmonyOS的`Image`组件有内置缓存机制
- 使用URL时会缓存图片，即使key变化，相同URL仍使用缓存
- 从PixelMap切换到URL时，可能显示旧的PixelMap缓存

**影响**：
- 图片被"锁定"显示为旧图片
- 切换页面时短暂显示上一页的图片
- 预加载的图片无法正确显示

### 问题2：缓存层级不同步

**缓存层级混乱**：
```
OnlineImageLoader.memoryCache (预加载系统)
      ↓ (不同步)
MangaViewer.pagePixelMaps (显示系统)
      ↓ (不可控)
Image组件内部缓存 (HarmonyOS)
```

**后果**：
- 预加载的图片存在OnlineImageLoader，但pagePixelMaps没有
- MangaViewer认为图片未加载，显示占位图或旧图
- Image组件使用自己的缓存，与应用层状态不一致

### 问题3：显示条件判断缺陷

**原有逻辑**：
```typescript
if (!this.shouldShowLoadingForPage(page) || this.pagePixelMaps.has(page.id)) {
  Image(this.singlePageImageInput)
}
```

**问题**：
- 即使图片未加载，也可能显示Image组件
- 此时`singlePageImageInput`可能是上一页的URL或PixelMap
- 导致显示错误的图片

## 三、架构解决方案

### 3.1 核心方法：`getDisplayImageInput`

**功能**：决定Image组件显示什么内容

**修复前**：
```typescript
private getDisplayImageInput(page: MangaPage): Resource | string | image.PixelMap {
  const pm = this.pagePixelMaps.get(page.id);
  if (pm) return pm;
  return this.getImageResource(page); // 问题：网络图片返回URL
}
```

**修复后**：
```typescript
private getDisplayImageInput(page: MangaPage): Resource | string | image.PixelMap {
  const pm = this.pagePixelMaps.get(page.id);
  if (pm) return pm;
  
  // 【架构修复】网络图片必须转换为PixelMap后才能显示
  if (page.sourceType === ImageSourceType.NETWORK) {
    // 网络图片如果没有PixelMap，返回占位图
    return $r('app.media.ic_image');
  }
  
  // 本地图片可以直接使用路径
  return this.getImageResource(page);
}
```

**关键改进**：
- ✅ 网络图片必须有PixelMap才返回真实内容
- ✅ 没有PixelMap时返回占位图，避免显示旧图
- ✅ 本地图片不受影响，保持原有逻辑

### 3.2 核心方法：`loadImageWithNewManager`

**功能**：使用统一缓存机制加载网络图片

**架构流程**：
```
1. 检查 pagePixelMaps (内存缓存)
   ↓ 命中 → 直接返回
   ↓ 未命中
2. 调用 ImageCacheManager.loadImage
   ↓ 尝试 OnlineImageLoader.memoryCache
   ↓ 尝试 DiskCacheManager
   ↓ 尝试 网络加载
   ↓ 获取 PixelMap
3. 同步 PixelMap 到 pagePixelMaps
   ↓
4. 如果是当前页，立即更新显示
   ↓
5. 完成
```

**关键代码**：
```typescript
private async loadImageWithNewManager(page: MangaPage, pageIndex: number): Promise<void> {
  // 1. 检查内存缓存
  const memCached = this.pagePixelMaps.get(pageId);
  if (memCached) {
    logger.debug(TAG, `[架构] 内存缓存命中: P${pageIndex + 1}`);
    return;
  }

  // 2. 从统一缓存系统加载PixelMap
  const cacheManager = ImageCacheManager.getInstance();
  const cachedPixelMap = await cacheManager.loadImage(url, { headers: this.networkHeaders });
  
  if (cachedPixelMap) {
    // 3. 【关键】同步PixelMap到pagePixelMaps
    this.pagePixelMaps.set(pageId, cachedPixelMap);
    this.pagePixelMaps = new Map(this.pagePixelMaps); // 触发响应式更新
    
    // 4. 【关键】如果是当前页，立即更新显示
    if (pageIndex === this.viewCurrentPageIndex) {
      logger.info(TAG, `[架构] 当前页PixelMap已就绪，立即更新显示`);
      this.updateSinglePageDisplay();
    }
    return;
  }

  // 5. 缓存未命中，说明加载失败
  throw new Error('网络加载失败：所有缓存层级均未命中');
}
```

**关键改进**：
- ✅ 所有网络图片都转换为PixelMap
- ✅ 立即同步到pagePixelMaps
- ✅ 当前页立即更新显示
- ✅ 触发响应式更新确保UI刷新

### 3.3 显示条件优化

**修复前**：
```typescript
if (!this.shouldShowLoadingForPage(page) || this.pagePixelMaps.has(page.id)) {
  Image(this.singlePageImageInput)
}
```

**修复后**：
```typescript
// 【架构修复】网络图片必须有PixelMap才显示Image组件
const shouldShowImage = page.sourceType === ImageSourceType.NETWORK 
  ? this.pagePixelMaps.has(page.id)  // 网络图片：必须有PixelMap
  : (!this.shouldShowLoadingForPage(page) || this.pagePixelMaps.has(page.id)); // 本地图片：保持原逻辑

if (shouldShowImage) {
  Image(this.singlePageImageInput)
}
```

**关键改进**：
- ✅ 网络图片必须有PixelMap才显示
- ✅ 避免显示占位图或旧缓存
- ✅ 本地图片不受影响

### 3.4 性能优化：`updateSinglePageDisplay`

**修复前**：
```typescript
private updateSinglePageDisplay(): void {
  // 强制递增renderEpoch，确保Image组件重新渲染
  this.renderEpoch = this.renderEpoch + 1;
  
  this.singlePagePageId = page.id;
  this.singlePageImageInput = this.getDisplayImageInput(page);
}
```

**修复后**：
```typescript
private updateSinglePageDisplay(): void {
  // 【架构优化】只在页面ID真正变化时才递增renderEpoch
  const pageChanged = this.singlePagePageId !== page.id;
  if (pageChanged) {
    this.renderEpoch = this.renderEpoch + 1;
  }

  this.singlePagePageId = page.id;
  
  // 【优化】只在imageInput真正变化时才更新
  const newImageInput = this.getDisplayImageInput(page);
  const inputChanged = this.singlePageImageInput !== newImageInput;
  if (inputChanged || pageChanged) {
    this.singlePageImageInput = newImageInput;
  }
}
```

**关键改进**：
- ✅ 避免频繁重建Image组件
- ✅ 减少不必要的渲染
- ✅ 提升性能和稳定性

## 四、架构优势

### 4.1 彻底解决图片锁定问题

**原理**：
- 网络图片永远不使用URL显示
- 只使用PixelMap显示
- 避免Image组件的URL缓存机制

**效果**：
- ✅ 图片不会被"锁定"为旧图
- ✅ 切换页面时不会显示上一页图片
- ✅ 预加载的图片能正确显示

### 4.2 统一缓存管理

**三级缓存同步**：
```
OnlineImageLoader.memoryCache
      ↓ (同步)
MangaViewer.pagePixelMaps
      ↓ (同步)
Image组件显示
```

**效果**：
- ✅ 预加载的图片能立即显示
- ✅ 缓存状态与显示状态一致
- ✅ 避免重复加载

### 4.3 本地漫画不受影响

**设计**：
- 所有判断都检查`page.sourceType`
- 只对`ImageSourceType.NETWORK`应用新逻辑
- 本地图片保持原有逻辑

**效果**：
- ✅ 本地漫画正常显示
- ✅ 不影响现有功能
- ✅ 向后兼容

### 4.4 性能优化

**优化点**：
- 减少renderEpoch递增频率
- 减少Image组件重建
- 减少不必要的渲染

**效果**：
- ✅ 更流畅的翻页体验
- ✅ 更低的内存占用
- ✅ 更快的响应速度

## 五、使用指南

### 5.1 预加载系统集成

预加载系统会自动将图片加载到`OnlineImageLoader.memoryCache`：

```typescript

```

### 5.2 阅读器显示

阅读器打开时，自动从缓存加载：

```typescript
// MangaViewer 自动调用
private async loadImageWithNewManager(page: MangaPage, pageIndex: number) {
  // 1. 检查 pagePixelMaps
  // 2. 从 ImageCacheManager 加载
  // 3. 同步到 pagePixelMaps
  // 4. 更新显示
}
```

### 5.3 状态管理

使用`ImageLoadStateManager`管理加载状态：

```typescript
// 开始加载
this.imageLoadStateManager.startLoading(pageId);

// 加载完成
this.imageLoadStateManager.onLoadComplete(pageId, pixelMap);

// 加载失败
this.imageLoadStateManager.onLoadError(pageId, errorMsg);
```

**图片不显示**：
1. 检查是否有`[架构] 内存缓存命中`或`缓存命中`日志
2. 检查是否有`当前页PixelMap已就绪`日志
3. 检查`hasPm=true`确认PixelMap已同步

**显示旧图**：
1. 检查`network=true`确认是网络图片
2. 检查`hasPm=true`确认有PixelMap
3. 检查没有使用URL显示

## 七、注意事项

### 7.1 PixelMap内存管理

- PixelMap占用内存较大
- 需要及时释放不用的PixelMap
- 使用`pagePixelMaps`统一管理

### 7.2 缓存同步时机

- 必须在获取PixelMap后立即同步到pagePixelMaps
- 必须触发响应式更新：`this.pagePixelMaps = new Map(this.pagePixelMaps)`
- 当前页必须立即更新显示

### 7.3 本地图片兼容

- 所有判断都要检查`page.sourceType`
- 只对网络图片应用新逻辑
- 本地图片保持原有逻辑
